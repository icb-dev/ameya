Commercial Project
Section Creation Guide

Learn how to create new dynamic sections for the Commercial Project admin panel in a scalable, production-ready way.

Architecture Philosophy

One Project → Multiple Sections → Each Section stored as JSON
This approach allows for maximum flexibility without requiring database schema changes.

Table of Contents

1. Core Database Concept

project_sections
├── id              (Primary Key)
├── project_id      (Foreign Key)
├── section_type    (String: "hero", "overview", etc.)
├── position        (Integer: Ordering)
└── data            (JSON: Flexible structure)

One Row Per Section

Each section is stored as a single database row

No Schema Changes

Add new sections without altering database structure

CMS-Friendly

Flexible JSON structure for easy content management

3. Step-by-Step Flow to Add a New Section

1

Define Section Requirements

  • What fields are required?
  • Is it dynamic (add/remove items)?
  • Single object or list of items?

💡 Pro Tip

Always finalize the data structure BEFORE coding.

2

Create Type Definition

// project.types.ts
export interface ExampleItem {
  title: string;
  image: string;
}

export interface ExampleSectionData {
  items: ExampleItem[];
}

⚠️ Important

Types must exactly match how data is saved and rendered.

3

Create Component

// ExampleSection.tsx
interface Props {
  data: ExampleSectionData;
  onChange: (data: ExampleSectionData) => void;
}
  • Component manages UI only
  • No API calls inside component
  • Use onChange to update parent state
4

Add State in CommercialProject Page

const [example, setExample] =
  useState<ExampleSectionData>({
    items: []
  });
5

Render Component

<ExampleSection
  data={example}
  onChange={setExample}
/>
6

Save Section to Database

if (example.items.length > 0) {
  await addSection({
    project_id: id!,
    section_type: "example",
    position: 10,
    data: example
  });
}

Success!

New section successfully added without backend or DB changes.

4. Golden Rules

One Section = One JSON

Each section is stored as a single JSON object

Frontend Controls Structure

Frontend defines the data structure

Backend Remains Generic

Backend doesn't need to know section structure

Filter Empty Data

Always filter empty data before saving

Types Drive Everything

TypeScript types ensure consistency across the application

5. Example Stored JSON

{
  "section_type": "faqs",
  "position": 9,
  "data": {
    "items": [
      {
        "question": "Is project RERA approved?",
        "answer": "Yes, it is RERA approved."
      }
    ]
  }
}
